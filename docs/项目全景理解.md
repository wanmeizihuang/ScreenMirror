# Wifi投屏（ScreenMirror）项目全景理解

> 整理日期：2026-07-22
> 范围：完整项目（docs / protocol / server / client/android / shared）
> 说明：本文基于对所有源码、协议实现与设计文档的实测阅读；以 `docs/实现方案.md` 与 `protocol/protocol-spec.md` 为权威口径。

---

## 0. 一句话结论

这是一个**已实现 Phase 1（Android → Windows 局域网投屏 + 反向控制）**的投屏软件。真实运行的架构与你记忆里的早期设计**有多处重大偏差**：协议是**手写二进制**而非 Protobuf，接收端解码用 **LibVLCSharp（VLC）**而非 FFmpeg+DirectX11，加密 **ECDH+AES 已实现但被置为不接线的空壳（实际明文）**，反向控制是**用 PC 操作手机**而非注入 Windows。

---

## 1. 项目目标与当前状态

- **目标**：手机屏幕实时镜像到 Windows，并支持用电脑键鼠反向操作手机；极简 UI。
- **分阶段**：
  - Phase 1（✅ 已落地）：Android 发送端 + Windows 接收端，局域网投屏 + 反向控制。
  - Phase 2（部分完成）：心跳保活已实现；分辨率降采样、音频通道、传输加密仍未实现。
  - Phase 3（规划）：iOS / macOS / 鸿蒙原生发送端、多设备同屏。
- **当前实际可用能力**：屏幕镜像（H.264）、反向控制（点击/拖拽/滚动/返回/Home）、UDP+mDNS 局域网发现。

## 2. 与早期设计的关键偏差（务必先读）

| 主题 | 早期/记忆描述 | 实际代码事实 |
|---|---|---|
| 协议 | TCP + **Protobuf** + 自定义二进制 | **纯手写二进制** `[Type][Len4][Payload]`；`messages.proto` 未被编译，Protobuf 依赖是死依赖 |
| 接收端解码 | FFmpeg P/Invoke + **DirectX 11 自研渲染** | 已废弃；改用 **LibVLCSharp**（VLC 内部 DXVA2/D3D11VA 硬解，VideoView 渲染），无手写 DX 代码 |
| 安全 | ECDH + AES-128 **已启用** | 算法两端均实现，但 `PerformHandshake` 是占位空壳、连接流程从不调用 → **全链路明文 TCP** |
| 发现 | mDNS 为主 | **UDP 广播(35357)为主**；PC 端 `DiscoveryService` 仅自定义 UDP JSON，**未实现 mDNS 查询** |
| 反向控制 | 收手机指令**注入 Windows** | 方向相反：PC 捕获鼠标/键盘 → 转发 Android 由无障碍服务注入（用 PC 操作手机） |
| 连接方向 | （隐含双向） | **仅手机主动连 PC**（PC 监听 35354）；PC 主动连路径代码存在但不可用 |
| 插件系统 | 5 层 + IPlugin 全端通用 | **仅 Windows 接收端有** IPlugin；Android 发送端为 ui/core/modules 务实分层 |

## 3. 架构总览

### 3.1 数据流（投屏 + 反向控制）

```
[Android 手机]
  MediaProjection ──► VirtualDisplay(Surface) ──► MediaCodec(H.264, 硬件)
        │                                                │
        │  NAL(Annex-B) 经回调 sendNal                   ▼
        │                          ControlConnection.send(VIDEO_FRAME)
        │                                      │
        │                            TCP 35354 (单通道复用)
        │                                      │
        ▼                                      ▼
  [反向控制接收]                    [Windows PC 接收端]
  AccessibilityService              ControlConnection 分包(ReadExact)
   ← Touch/Mouse/Key 解码              │
        ▲                              ▼
        │                   MirrorWindow.OnMessageReceived(VIDEO_FRAME)
        │                              │
        │                   VlcDecoder.WriteNal ──► NalStream(队列,背压)
        │                                              │
        │                                       LibVLC(demux=h264)
        │                                              │
        │                                       VideoView 渲染
        │
  [PC 端反向控制采集]                       
  LowLevelMouseHook/KeyboardHook
   (仅当鼠标位于投屏窗上)
        │
        └── Encode ──► TCP 35354 ──► Android
```

### 3.2 端口与通道

| 端口 | 用途 | 状态 |
|---|---|---|
| 35354 | TCP 主通道：DEVICE_HELLO / SCREEN_INFO / STREAM_* / 控制消息 / **VIDEO_FRAME** | ✅ 单通道复用 |
| 35355 | TCP 视频独立端口（常量 `DefaultVideoPort`） | ❌ 死代码（单通道后不再分用） |
| 35356 | TCP 音频独立端口（常量 `DefaultAudioPort`） | ❌ 死代码 |
| 35357 | UDP 发现/广播（discover / present JSON） | ✅ 主发现方式 |

### 3.3 分层（接收端 L1–L5，发送端务实分层）

接收端 5 层（依赖自下而上）：
- **L1 协议层** `protocol/csharp`（ScreenMirror.Protocol，被 server 引用）：编解码、连接、路由。
- **L2 核心/基础设施层** `server/src/core` + 协议库的 ConnectionManager/ControlConnection/MessageRouter：发现、安全、TCP 监听/分包。
- **L3 插件框架层** `server/src/plugins/IPlugin.cs`：IPlugin / PluginManager / PluginMessage。
- **L4 功能模块层** `server/src/modules`：screen-mirror（IPlugin 空壳）、vlc-decoder（非插件）、reverse-control（IPlugin）。
- **L5 UI 层** `server/src/ui`：MainWindow（组合根/设备列表）、MirrorWindow（投屏渲染窗）。

发送端（Android，非插件化）：`ui`(MainActivity) → `core`(ScreenCaptureService / DeviceDiscoveryService / SecurityManager / AudioStreamEncoder / WifiDirectManager) → `modules`(ReverseControlService) → 共享 `protocol/kotlin`（经 sourceSets 并入）。

## 4. 通信协议（protocol/）

### 4.1 帧格式（两端一致）
```
[0]     1B  Type   (消息类型，见下表)
[1..4]  4B  PayloadLength (大端 uint32，上限 4MB，用于容纳大 I 帧)
[5..]   NB  Payload (变长)
```
- 头部固定 **5 字节**；早期为 2 字节曾因大 I 帧(200–500KB)溢出导致协议错位，已升级为 4 字节。
- 分包/粘包：`ReadExactAsync` / `DataInputStream.readFully` 严格按长度读满，根本规避拆包/粘包。

### 4.2 消息类型清单

| Type | 名称 | 方向 | 负载布局 | 实现状态 |
|---|---|---|---|---|
| 0x01 | TOUCH_EVENT | PC→Phone | Action+X(×10000)+Y+Pressure+EventTime(16B) | ✅编解码齐 |
| 0x02 | KEY_EVENT | PC→Phone | Action+KeyCode+MetaState+EventTime(17B) | ✅ |
| 0x03 | SCREEN_INFO | Phone→PC | W+H+DPI+FrameRate+Codec+MaxBitrate+HasAudio+AudioCodec+Rotation(19B) | ✅ |
| 0x04 | DEVICE_HELLO | 双向 | Version+DeviceType+DeviceName(2+N) | ✅ |
| 0x05 | HEARTBEAT | Phone→PC | Timestamp(8B) | ✅每 3 秒发送 |
| 0x06 | HEARTBEAT_ACK | PC→Phone | Timestamp(8B) | ✅回显时间戳 |
| 0x07 | STREAM_START | Phone→PC | 空载 | 透传 |
| 0x08 | STREAM_STOP | 双向 | 空载 | 透传 |
| 0x09 | STREAM_PAUSE | PC→Phone | 空载 | 枚举定义，未处理 |
| 0x0A | STREAM_RESUME | PC→Phone | 空载 | 枚举定义，未处理 |
| 0x0B | MOUSE_EVENT | PC→Phone | Action+X+Y+Button(6B) | ✅ |
| 0x0C | SCROLL_EVENT | PC→Phone | X+Y+HScroll+VScroll(8B) | ✅ |
| 0x0D | ROTATION_CHANGE | Phone→PC | 仅枚举，**无编解码** | ❌ |
| 0x0E | ERROR | 双向 | ErrorCode+Message(4+N) | ✅ |
| 0x20 | CLIPBOARD_SYNC | 双向 | Phase 2 预留 | ❌未实现 |
| 0x21 | FILE_TRANSFER | 双向 | Phase 2 预留 | ❌未实现 |
| 0x22 | VIDEO_FRAME | Phone→PC | **H.264 NAL 原始字节(含 00 00 00 01 起始码)** | ✅裸透传 |

> `messages.proto` 定义了更丰富的 `Envelope{type,payload,timestamp,request_id}` 与 CAPABILITY/CLIPBOARD/FILE_TRANSFER 等，但**从未被编译或接入**，仅作规划参考。

## 5. 设备发现

- **Android 端**：`DeviceDiscoveryService`
  - 广播自己：`NsdManager.registerService`（`_screenmirror._tcp`） + 另起 UDP 监听 35357。
  - 发现 PC：`NsdManager.discoverServices` + `scanByUdp()`（遍历网卡、跳过虚拟网卡、算广播地址、发 discover JSON、等 present 响应）。
  - `getLocalIpAddress` 优先 192.168.* / 10.* / 172.16-31.*。
- **Windows 端**：`DiscoveryService`
  - UDP 35357 广播自己（JSON：`screenmirror.discover`，device_type=windows）+ 监听响应回 `present`。
  - 尝试 `netsh advfirewall` 加防火墙规则（非管理员静默失败）。
  - ⚠️ **未引用任何 mDNS/Zeroconf 库**，PC 端无 mDNS 查询实现。

发现 JSON 示例（手机广播）：
```json
{"type":"screenmirror.discover","device_name":"...","device_type":"android","version":1,"port":35354,"mac_suffix":"...","has_audio":false}
```

## 6. 安全机制现状（已实现但未启用）

- `SecurityManager`（C# `server/src/core/SecurityManager.cs` 与 Kotlin `core/SecurityManager.kt`）：
  - ECDH（C# nistP256 / Kotlin secp256r1）生成密钥对。
  - `DeriveSharedKey` → HKDF-SHA256（info=`ScreenMirror-AES-128-GCM`）→ 16 字节 AES-128 密钥。
  - `Encrypt/Decrypt`：AES-128-GCM，输出 `Nonce(12)+Cipher+Tag(16)`。
  - `GeneratePairingCode`：4 位随机配对码（未接入 UI）。
- **关键缺口**：`SecureConnection.PerformHandshake` 是框架占位（公钥收发被注释、直接 `return true`），连接流程从不实例化/调用 `SecurityManager`/`SecureConnection` → **所有流量明文**。
- 这是从「设计完整」到「实现落地」之间最明显的断层。

## 7. 反向控制

- **方向**：用 PC 操作手机。
- **PC 端采集**（`ReverseControlPlugin` + `LowLevelMouseHook`/`LowLevelKeyboardHook`）：
  - `WH_MOUSE_LL`(14) / `WH_KEYBOARD_LL`(13) 低级别钩子，须在 UI 线程安装。
  - 仅在 `IsCursorOverMirrorWindow()`（投屏窗为前台或光标位于其上）时转发，避免误控 PC。
  - 坐标：`GetCursorPos`+`GetWindowRect` 得相对坐标 → 归一化 0~1 → 按屏幕旋转 90/180/270 修正。
  - 键码：Windows 虚拟键码经 `WindowsKeyCodeToAndroid` 映射到 Android KeyEvent。
- **Android 端注入**（`ReverseControlService`，AccessibilityService）：
  - `onServiceConnected` 反射获取 `InputManager.injectInputEvent`（需系统/签名权限）。
  - 触摸：主线程通过 `dispatchGesture(GestureDescription)` 累积 Path（DOWN/MOVE/UP）。
  - 滚轮：转换为纵向/横向滑动手势。
  - 导航：右键/Esc/Home 通过 `performGlobalAction` 可靠降级；普通文本键仍受系统权限限制。

## 8. Android 发送端详解（client/android）

- **工程**：单一 `:app` 模块（非多模块）。`app/build.gradle.kts` 用 `sourceSets { java.srcDirs("../../../protocol/kotlin") }` 把共享协议源码直接并入。
- **入口**：`ui/MainActivity.kt`（唯一 Activity，Compose UI，无自定义 Application）。
  - `onCreate`：bind ScreenCaptureService、startAdvertising(35354)、进入 Compose。
  - 界面：发现列表（扫描设备/手动 IP）、投屏按钮、反向控制无障碍提示、投屏中态。
  - 投屏链：`requestMediaProjection` → `MediaProjectionManager` → `connect(host,35354)` → `sendDeviceHello` → `startCapture(sendNalCallback)`。
- **采集+编码**（`core/ScreenCaptureService.kt`，前台 Service + 保活）：
  - `MediaProjection` → `VirtualDisplay(inputSurface)` → `MediaCodec.createEncoderByType(AVC)`，全程 Surface 硬件通路。
  - 分辨率降采样到 `maxDim=1280`（16 字节对齐）；码率默认 **8 Mbps**（文档称 ~4M，实际 8M）、帧率 30、I 帧间隔 2s、VBR、Q+ 低延迟。
  - SPS/PPS 在 `INFO_OUTPUT_FORMAT_CHANGED` 从 csd-0/csd-1 取出，单独作为 NAL 先发。
  - `normalizeToAnnexB`：AVCC 长度前缀 → Annex-B `00 00 00 01` 起始码。
- **发送**（`protocol/kotlin/Protocol.kt` 的 `ControlConnection`）：`tcpNoDelay=true`、256KB 发送缓冲；视频与控制共用 35354；`sendNal` 回调 → `sendMessage(VIDEO_FRAME, nal)`。
- **未接线（死代码）项**：`AudioStreamEncoder`(AAC)、`WifiDirectManager`(P2P)、`vPort/aPort` 直连分支（因 sendNal 回调恒非空而永不走）、STREAM_PAUSE/RESUME。

## 9. Windows 接收端详解（server）

- **工程**：2 个程序集——`ScreenMirror.Protocol`(`protocol/csharp`，被引用) + `ScreenMirror`(`server/src`，WinExe/WPF/net8.0-windows)。仅 `.csproj` 无 `.sln`。NuGet 仅 `LibVLCSharp.WPF` + `VideoLAN.LibVLC.Windows`。
- **入口**：`App.xaml`(StartupUri=MainWindow) → `MainWindow.xaml.cs`：组合根，实例化 Discovery/Connection/Router/PluginManager + 两插件，启动监听与发现，连接建立后开 MirrorWindow。
- **TCP**：`ConnectionManager.StartListeningAsync(35354)` 经 `TcpListener` 接受连接 → 封装 `ControlConnection` → `MessageRouter.BindToConnection` 分发。
- **解码渲染**（`modules/vlc-decoder`）：
  - `VlcDecoder.Initialize`：`LibVLC` 低延迟参数（`--network-caching=200 --clock-jitter=100 --demux=h264 --avcodec-skiploopfilter=1`），绑定 `VideoView.MediaPlayer`。
  - `NalStream`：自定义 `Stream`，`ConcurrentQueue` + `SemaphoreSlim`，队列超 60 丢最旧（简化背压）；`Read` 阻塞等 500ms（避免 VLC 误判流结束）。
  - `MirrorWindow.OnMessageReceived`：VIDEO_FRAME → `VlcDecoder.WriteNal`；`DispatcherTimer` 1s 检测 NAL 计数，连续 3s 无帧显示"信号丢失"，6s 重置。
- **渲染**：由 LibVLCSharp `VideoView` 内部 DXVA2/D3D11VA 完成，无手写 DX11 代码。
- **插件系统**（`plugins/IPlugin.cs`）：`IPlugin`(Name/Version/State/Initialize/Start/Stop/GetCapabilities/HandleMessage/SubscribedMessageTypes) + `PluginManager`(生命周期 + 向 MessageRouter 挂订阅)。实现：`ScreenMirrorPlugin`(空壳)、`ReverseControlPlugin`。`VlcDecoder` 非 IPlugin，由 MirrorWindow 直接实例化。

## 10. 未实现 / 死代码清单（值得后续推进）

1. **传输加密**：ECDH+AES 算法就绪，仅需把 `PerformHandshake` 接线并接入连接流程 → 实现明文→加密。
2. **音频通道**：`AudioStreamEncoder` 与 `HasAudio`/`AUDIO_AAC` 枚举就位，但两端均无音频链路。
3. **心跳保活**：已接线；Android 每 3 秒发送，双端 10 秒无入站数据主动断开。
4. **分辨率降采样**：当前硬编码（手机原生 / 8Mbps），无动态降采样。
5. **mDNS（PC 端查询）**：仅 Android 注册 + 自定义 UDP；PC 端未做 mDNS 查询。
6. **PC 主动连接手机**：代码有 `ConnectAsync`，但手机不监听 TCP。
7. **多设备同屏**：`ConnectionManager` 支持多连接字典，但 MainWindow 用单 `_activeConnection` 限制单设备。
8. **反向控制文本输入**：导航键已有公开API降级；普通字母键和完整文本输入尚无通用实现。
9. **`messages.proto` 与 `shared/`**：均为"规划残留"——前者未编译，后者为空目录。
10. **`ROTATION_CHANGE` / `CLIPBOARD_SYNC` / `FILE_TRANSFER`**：枚举或单侧存在，未实现。

## 12. 后续可推进方向（建议）

- **优先级高**：接通安全握手（ECDH+AES）消除明文传输；修复反向控制按键注入降级方案。
- **优先级中**：实现音频通道、PC 端 mDNS 查询、动态码率。
- **优先级低 / 规划**：Phase 2/3 多端发送端、多设备同屏、`messages.proto` 真正落地或清理死代码。
